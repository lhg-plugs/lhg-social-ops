# lhg-so-distribute：多平台分发策略

> 目标：一篇内容，吃透 N 个平台。
> 核心纪律：**一稿多发 ≠ 复制粘贴；每个平台都要按它的脾气改写。**

## 1. 何时使用

- 内容已产出（文案/视频），准备分发到多个平台时
- 用户说"帮我把这篇发到各平台"时 → 出改写策略，**不执行发布**
- 复盘发现"某平台数据持续差"，回来查分发策略（大概率是直接复制粘贴惹的祸）

## 2. 输入与输出

- **输入**：一篇原始内容 + 目标平台列表（1-3 个）
- **输出**：分发清单——每个平台的改写要点、标题、开头、标签、发布时间、注意事项

## 3. 第一步：平台调性卡

先给每个目标平台建一张"调性卡"（一次建好，长期复用，存 `distribute/platform-cards.md`）：

```markdown
## <平台名>调性卡
- 内容形态：<图文/短视频/中长视频/问答>
- 标题风格：<如：小红书=情绪+结果前置；公众号=信息+悬念>
- 开头黄金 3 秒：<前 3 秒/前 50 字必须出现什么>
- 篇幅：<如：小红书 300-800 字；公众号 1500-3000 字>
- 标签：<数量/风格，如：抖音 3-5 个偏口语>
- 发布时间窗口：<如：12:00-13:00，20:00-22:00>
- 禁忌：<如：知乎忌情绪化标题；B 站忌纯营销>
- 审核红线：<该平台特有的敏感点>
```

调性卡是改写的依据，没有调性卡就改写 = 凭感觉。

## 4. 第二步：一稿多发改写清单

对每个平台输出改写清单（不是全文改写，是"怎么改"的指令 + 关键部位示例）：

```markdown
# 分发清单：<内容标题>（<日期>）
## 原稿摘要
<一句话：这篇讲什么>
## 平台 A（<平台名>）
- 标题改写：<按调性卡重写，示例>
- 开头改写：<前 50 字/3 秒重写，示例>
- 结构调整：<如：长文拆 3 段发；视频加封面标题>
- 标签：<2-5 个>
- 发布时间：<具体时间>
- 注意事项：<如：去掉原稿里的外部链接，该平台不给流量>
## 平台 B……
```

### 改写四件套（每个平台必做）
1. **标题**：按平台标题风格重写，不许原标题直发（公众号标题发小红书，99% 哑火）。
2. **开头**：前 50 字/3 秒按"黄金开头"重写——这是平台间差异最大的部位。
3. **篇幅**：长的拆短的，短的扩充，不许"一篇 3000 字发遍全网"。
4. **标签**：按平台标签习惯重配，不许一套标签全网通用。

## 5. 第三步：分发顺序与间隔

- **首发平台**：内容最契合的那个平台先发（通常是粉丝最精准的）。
- **间隔**：平台间间隔 ≥ 4 小时（防"自己抢自己流量"，也给首发留发酵时间）。
- **顺序**：粉丝精准度从高到低，不要反过来（公域大平台首发，精准小池子捡漏 = 浪费）。

## 6. 第四步：发布执行（人工）

本插件**不提供自动发布**，原因：

1. 各平台反爬/反营销策略严，自动化发布易触发风控，**封号代价用户承担不起**。
2. 发布前的人工最后一眼（标题错字、标签、封面）是质量门，机器代劳不了。
3. 执行层已有成熟工具（如 AINightCoder/claude-code-social-skills 这类发布向 skill，走浏览器自动化 + 人工确认），本插件与其互补，不重复造轮子。

发布前检查清单（人工逐条打勾）：
- [ ] 标题按平台改写了吗？
- [ ] 极限词/违禁词扫过吗？（跑 `/lhg-social-ops:audit`）
- [ ] 标签 2-5 个吗？
- [ ] 发布时间对吗？
- [ ] 该平台的禁忌避开了吗？

**硬门**：任何自动发布命令（如一键发布脚本、定时群发）都会被本插件的发布拦截门拦下。如确需自动化，走专用发布工具并自行承担风控后果。

## 7. 分发效果追踪

每篇内容分发后，把各平台版本的数据分别记入 `data/posts.json`（platform 字段区分版本），复盘时才能回答"这篇在 A 平台爆、在 B 平台哑，是内容问题还是改写问题"。

### 改写示例（一篇变两篇）

原稿（公众号长文）：《从宁德时代 Q3 财报，看动力电池的三个真相》（2800 字，信息密度高）

**→ 小红书版改写清单**：
- 标题：`宁德财报我看了3遍，发现3个散户不知道的真相😱`（情绪+结果前置+数字）
- 开头：前 50 字直接给结论——"先说结论：Q3 最危险的不是利润下滑，是这一个指标"，原文铺垫 300 字全删
- 篇幅：2800 字 → 600 字，只留 3 个真相+每点 1 个数据
- 标签：#宁德时代 #财报 #新能源 #股票 #投资
- 发布时间：20:00（小红书晚间流量高峰）
- 注意：去掉原文里的外部研报链接，换成"评论区要研报原文的扣 1"

**→ 抖音版改写清单**：
- 标题（封面大字）：`宁德财报的3个真相`
- 开头 3 秒：口播"宁德时代 Q3 财报，有一个数字很吓人"（悬念，不剧透）
- 结构：3 个真相拆成 3 条 40 秒短视频，分 3 天发（间隔 ≥ 4 小时）
- 标签：#财经 #宁德时代 #股票知识
- 发布时间：12:30（午间流量）
- 注意：口播稿禁提"买入/卖出"类荐股词，违禁词先扫一遍

同一篇原稿，两个平台版本除了"3 个真相"这个核，标题/开头/篇幅/节奏全不一样——这就是改写，不是复制。

### 一句话检验改写质量

把两个平台版本并排放，问三个问题：
1. 标题能互换吗？→ 能，说明没改写，重做。
2. 开头 50 字/3 秒一样吗？→ 一样，重做。
3. 删掉平台名，还能看出这是给哪个平台写的吗？→ 看不出，重做。

## 8. 反模式（不要这么做）

- ❌ 原标题原内容全网复制粘贴——这是分发策略的头号死法
- ❌ 5 个平台同时发——自己抢自己流量，还没法归因
- ❌ 长文不拆直接发短视频平台——形态错配，必哑火
- ❌ 一套标签全网通用——每个平台的标签生态不一样
- ❌ 用自动化脚本批量发布——封号了别找我，硬门就是为此设的
- ❌ 分发不记数据——复盘时分不清是内容不行还是改写不行

## 9. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 每个平台都按改写四件套做了吗？→ 有直发的，下次必须改写。
2. 分发间隔 ≥ 4 小时吗？→ 没有就调。
3. 发布前检查清单过了吗？→ 没过不许发。
4. 各平台版本数据分别记录了吗？→ 没记，复盘没法做。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：拿一篇公众号长文走一遍本 skill，输出小红书+抖音两个版本的改写清单，检查四件套是否齐、禁忌是否避开。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-social-ops/issues。
